Setup overview

Plug a USB-C wall charger rated 5 V, 2 A or more into the robot’s main USB-C port. Leave the unit powered at its desk.

For your first setup, power one robot at a time. Look for its setup Wi-Fi name or a home-network address on its screen.

  1. On your phone or tablet, open Wi-Fi settings. Join TinyEngineer-XXXX, matching the four characters on the robot. Choose to stay connected if Android says “No internet.”
  2. Open Wi-Fi setup Keep the builder’s calibration. Tap Skip on Servos, or Parts are on → Next: Screen on older units. Continue through screen, lights and speaker.
  3. At Connection or Network, choose Wi-Fi. Enter your home 2.4 GHz Wi-Fi name and password, set the hostname to , then tap Connect to WiFi. Write down the numeric address it shows.
  4. Return your tablet to home Wi-Fi. Unplug the robot once and plug it back in.

Already joined your network? Continue with the address your builder gave you.

Switching tablets later? On the same Wi-Fi, open My robots → Share robot address on the first tablet and open the link on the second.

Open the robot’s page on the selected device. You can make it move by tapping the animation buttons.

Full instructions and tablet handoff

Connect the first robot

  1. Power one unit. Plug a 5 V USB charger rated for at least 2 A into the robot’s main USB-C port. The tablet can stay unplugged.
  2. Join its setup Wi-Fi. On your phone or tablet, open Wi-Fi settings and select TinyEngineer-XXXX with the four characters shown on the robot. Stay connected if Android says “No internet.”
  3. Open the setup screen. It may open automatically. Otherwise use the button below while connected to the robot.
Open Wi-Fi setup
  1. Keep the builder’s settings. On Servos tap Skip. If you see Parts are on → instead, tap that and then Next: Screen with the saved limits. Continue through Screen, RGB mapping and Speaker.
  2. At Connection or Network, select Wi-Fi if asked. Enter your 2.4 GHz network name and password. Set Hostname to tiny-01 and tap Connect to WiFi. Note the numeric address in the success message.
  3. Return to home Wi-Fi. Unplug the robot once, then plug it back in. Open unit 1’s Animations and tap Bell. You should see that unit strike the bell. Repeat with tiny-02 through tiny-05.

Already showing a home-network address? Open that address on the same Wi-Fi, tap Animations → Bell, and skip directly to My robots.

Change tablet or Wi-Fi

Same Wi-Fi, new tablet. Leave the robot powered. Open its saved address on the other tablet. Enter the robot’s access token there if prompted. In My robots, “Share robot address” sends the link. Automatic reactions follow the coding session on its host computer.

Different Wi-Fi. If Config has WiFi networks, add the destination network, tap Add network, then Save settings. Power up at the new desk. Current source supports five saved networks. On the v0.2.0 release, power up at the destination. When the old network cannot be found, the robot opens its setup Wi-Fi again. Follow the Wi-Fi step with the same hostname.

Missing setup network, address or movement

Confirm the main USB-C port and charger. A robot already connected to the builder’s or your network uses its normal address. In Wi-Fi mode, if the saved network is unavailable, wait for the boot connection attempts to finish. A unit delivered in USB-only mode needs the builder to return it to Wi-Fi mode.

If the name fails, use the numeric address from setup, the robot’s boot display when shown, or your router’s connected-device list. Use the same home network as the robot. A guest network can block communication between devices. If the robot resets on movement, check the charger and cable.

If the browser requests an access token, get the device token from the builder. The Wi-Fi password belongs on the robot’s setup page. A factory reset is unnecessary for a tablet change.

Connect a coding app

You can use the robot’s buttons with a tablet alone. For automatic reactions, run the coding session on an awake computer that can open the robot’s own page. Your tablet can control that session remotely. A cloud-only chat has no direct route to the robot at your desk.

Claude Code

  1. On the computer that runs Claude Code, open the robot’s Animations page and tap Bell. The builder should install a current Node.js LTS on that computer.
  2. In the coding project, run the project’s installer below. Choose HTTP/Wi-Fi if asked, confirm the selected address, and enter the robot token privately if one was set. Confirm the changes. The installer adds this project’s Claude hooks and saves the default robot for this computer user.

  1. Open a fresh Claude Code session in that project. Ask “Read the README and give me one sentence about it.” The robot reads and rings when the turn finishes.
  2. For tablet use, enter /remote-control in that local session. Open the displayed link on Android or select the session in the Claude app under Code. This requires a supported Claude subscription and the host to stay awake.
Five desks or an old target

Claude’s installer saves the address per computer user. Installing for another desk can redirect other projects owned by that user. For simultaneous projects on one computer, have the builder give each project its own Tiny Engineer URL override and matching token when needed, kept private. The installer’s diagnostic command is npx -y tiny-engineer doctor. Verify each project by watching its intended unit.

Codex

Tiny Engineer’s installer has no Codex option. This guide supplies two local Codex hooks. Change these gestures in step 5 of the setup wizard.

  1. On the computer running local Codex, open the robot’s Animations page and tap Bell. Install a current Node.js LTS and make sure Codex can run node. For a protected robot, have the builder set the private environment variable for the Codex process.
  2. On that computer, open this guide in desktop Chrome or Edge and select the project folder using the button below. This adds two entries to .codex/hooks.json. Reinstalling with a different unit retargets this guide’s entries in that project.

  1. Open a fresh local Codex session in the trusted project. Use /hooks in the Codex CLI to review and trust both commands. Ask “Reply with the word ready.” Watch for the two selected gestures. A quick reply can make the first movement brief.
  2. On a supported Mac or Windows host, open the ChatGPT desktop app and choose Settings → Connections → Control this Mac or PC → Set up (or Add). Scan its QR code with the Android device and approve with the same account and workspace. In ChatGPT mobile choose the connected computer and that project. Keep the computer awake. Repeat the prompt on the tablet to verify the handoff.
Using a tablet during installation

“Copy setup for builder” includes the target and both complete hook definitions. Give it to the person configuring the computer. The folder picker must operate on the computer’s actual project. Copying instructions alone does not install the hooks.

No automatic movement

Test Bell from the coding computer first. Then verify that Codex is working in the project you selected, the hooks are trusted, Node is on the host app’s PATH, and any device token is available to that same process. Open a new session after changing hooks or credentials. In a managed workspace, an administrator can restrict hooks.
