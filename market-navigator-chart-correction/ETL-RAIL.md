# Verified ETL rail

The owner authorized both continued chart validation and the follow-on ETL status/rerun controls. Integration uses the existing ee38-based builder and shared chart, preserving default/baseline routes.

The left-rail ETL view separates loaded package identity and verified resource receipts from available publication, provider qualification and actual workflow status. The scoped JSON adapter validates the descriptor's content-derived version, then each requested resource's SHA-256 before returning parsed JSON. It caches only that coherent package and exposes read-only receipts. Native/provider values, source times and model calculations remain unchanged. A substituted JSON resource is rejected; an already rendered chart is retained. Initial integrity failures do not automatically retry. Transient initial-load errors receive at most three attempts with backoff. Each new live chart snapshot records its captured package identity; legacy saved evidence is not assigned the current package.

The ETL surface includes a content-bound application build ID, manifest URL/hash, verified loaded-resource count, index/model as-of, separate NOW/Analyze/Library identities, Level 0/1/3 qualification and limitations, per-source cadence/latest observation/count/collection time, and expandable receipts. Available-publication failures and job API failures do not erase loaded proof. Workflow runs/jobs/steps come from the actual synchronization workflow API, with clear unavailable states. Polling occurs once per minute for an active job while ETL is visible and stops on navigation/hidden document. Viewing/refreshing status sends GET requests only.

Run ETL on GitHub opens the existing workflow's authenticated manual control. The owner signs in, selects main and enables the full-history recheck input when wanted. GitHub enforces workflow permissions; no PAT or other repository credential is put into HTML, browser storage or public data. This is an explicit GitHub handoff, not one-click in-app dispatch. The previous dormant Cloudflare gateway is not deployed or represented as live by this release.

New tests cover every catalog source row, loaded and per-consumer package identity, real receipt/descriptor agreement, stage rendering, failed/unavailable workflow states, available-publication failure isolation, manual control destination, mobile bounds, NOW preservation, parked Analyze restoration, resource substitution and invalid descriptor rejection without automatic retries. Existing source/model/chart/reference/Data/selector/config/date gates remain. Hosted exact-source qualification and independent public verification precede delivery.
