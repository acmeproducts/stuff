# GY-016 — syntax-only JavaScript checks can miss async line-terminator runtime failure

## Failure

The owner observed:

`SOT-turn01-base.html:72 Uncaught ReferenceError: async is not defined`

A line break between `async` and `function` can still be syntactically valid JavaScript because `async` is parsed as an identifier statement, but it fails at runtime when that identifier is evaluated.

## Why this escaped

Per-script and combined `node --check` gates validate syntax only. They do not prove that line-terminator-sensitive constructs have the intended runtime semantics. The intended real-browser boot gate would catch this, but installer/qualifier failures prevented that gate from completing in earlier candidates.

## Permanent rule

- Exact generated and exact public artifacts must execute in a real Chrome/Edge browser before qualification.
- `node --check` remains necessary but never sufficient.
- The qualifier must explicitly reject any declaration hazard matching `async` followed by a line terminator before `function`.
- Installer/qualifier code itself must be structurally audited before execution; a failure in the QA harness is a release failure, not an excuse to expose the owner to an unvetted surface.
- The owner is not the runtime harness.
