# GY-012 — Pre-cutover-only JavaScript syntax qualification allowed a broken public artifact

## Rejected approach

Treating a syntax check of a temporary/generated JavaScript extraction as sufficient evidence that the owner-facing public HTML is safe to test.

## Failure

Base-25 reported `NODE_UI ok` and `MECHANICALLY QUALIFIED`, yet the owner-facing browser produced a JavaScript syntax error.

Therefore the old gate proved the wrong thing: it proved one intermediate extraction parsed under Node, not that the exact public bytes loaded and booted successfully in the target browser environment.

## Permanent rule

A SOT candidate is not mechanically qualified until the **exact public artifact** is fetched after cutover and independently passes:

- per-script syntax parsing;
- combined-script syntax parsing;
- browser/DOM boot smoke;
- zero `SyntaxError` / uncaught initialization exceptions;
- application-root render confirmation;
- release identity confirmation.

The qualification success marker and test URL are forbidden before those checks pass.

Owner/device testing is never a substitute for a preventable parser/boot check.

## Recovery

Base-25 remains failed evidence only. Rebuild the next candidate from the governed clean lineage, not from Base-25 generated HTML.
