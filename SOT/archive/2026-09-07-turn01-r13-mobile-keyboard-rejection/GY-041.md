# GY-041 — R13 owner rejection: mobile tag keyboard dismissal

Date: 2026-09-07

R13 mechanically qualified and corrected the flat Profile layout, but owner mobile testing rejected the tag editor because the software keyboard is still dismissed while typing. This violates the mobile-first interaction contract.

Observed defect:

- focusing the Profile tag editor opens the mobile keyboard;
- background refresh/redraw can still replace the active editor after mobile focus transitions, causing the keyboard to hide before the user can finish typing or press Enter.

R13's `editingSurface()` guard is insufficient because mobile browsers can transiently move `document.activeElement` during keyboard/viewport transitions. Focus presence cannot be the only redraw lock.

Required correction:

- treat active tag editing as explicit application state, not an inference from `document.activeElement`;
- set a durable tag-edit lock on `focusin`/pointer interaction with the editor and keep it through typing, suggestion selection and Enter assignment;
- background polling may update data while this lock is active but may not replace the editor DOM;
- clear the lock only on an explicit user interaction outside the tag-editor surface or navigation away;
- retain Enter-to-assign, type-ahead suggestions, chip `×` removal, hierarchy, master/detail and selection state;
- the correction is a clean UI-only source advance from the governed R13 composition. Do not patch the installed/generated HTML.

Backend and schema 6 remain unchanged.
