# GY-013 — whole-document compatibility token lint overriding real parser/browser gates

## Rejected approach

Reject release qualifiers that scan the entire regenerated application for broad text tokens such as `?.` or spread syntax and fail solely because those tokens exist anywhere in preserved ancestor code.

## Why rejected

This creates a second, text-based syntax authority that can contradict the actual JavaScript parser and browser boot gates. In Base-26 it rejected clean inherited code before the exact generated artifact could reach the parser/boot checks that were specifically added to prevent syntax defects.

The failure was preventable and mechanical. It was not an owner/device issue.

## Permanent rule

- The exact generated artifact and exact public read-back must be syntax-parsed and browser-booted.
- Those executable gates are the authority for complete-artifact JavaScript compatibility.
- Style/compatibility lint for newly authored code may be used only when scoped to that new delta and must not reject protected ancestor code by token presence alone.
- A text marker, HTTP 200, or broad grep is never a substitute for parsing and boot execution.
