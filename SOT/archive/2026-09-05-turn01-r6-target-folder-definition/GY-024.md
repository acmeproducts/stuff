# GY-024 — Destination picker cannot create the destination it asks the operator to choose

Date: 2026-09-05
Status: REJECTED LIMITATION

## Owner observation

During R6 owner testing, Target definition can only select an already-existing folder. The operator must leave SOT and create a folder elsewhere before returning to complete Target setup.

## Why this is rejected

Target and Backup definition are storage-management actions. The destination picker already owns volume discovery, folder browsing, selection, and validation. Requiring an out-of-band folder-creation step breaks the direct-action model and turns a simple missing destination into manual filesystem work.

The qualified backend already exposes the governed folder-creation operation at `POST /api/sot/turn01/fs/folder` with `{parent,name}` and validates/creates the directory through the same storage authority used by the picker.

## Replacement contract

1. Target and Backup pickers expose `New folder` while browsing a writable destination.
2. Folder creation occurs inside the picker through `POST /turn01/fs/folder`.
3. After successful creation, the picker enters the new folder and selects it as the Target/Backup candidate immediately.
4. The operator can then save the destination without leaving SOT.
5. Folder-creation failures are shown inline/actionably; raw technical detail remains diagnostic only.
6. Source selection remains selection-only; SOT must not encourage creating empty Source folders.
7. R6 remains the accepted SSOT/action surface baseline. R7 is a direct source revision of that accepted baseline, not a patch-forward from rejected UI lineage.
