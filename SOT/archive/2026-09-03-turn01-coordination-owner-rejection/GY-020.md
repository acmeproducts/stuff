# GY-020 — Static coordination qualification presented as behavioral proof

**Status:** REJECTED  
**Decision date:** 2026-09-03  
**Evidence:** owner browser gate against build `2026.09.03.sot-turn01-coordination-1`

## Owner gate result

The installed coordination build was healthy at schema 5 and publicly reachable, but owner testing failed gates 1, 3, 4, 5, 6, and 7. Only same-project conflict blocking passed.

Failed behavior:

1. Cross-project independence was not preserved.
2. Completed indexed state did not remain stable through refresh/reload.
3. Re-index did not preserve the prior valid evidence until replacement evidence committed.
4. Plan/evidence revision truth was not stable.
5. Background refresh still disrupted operator interaction state.
6. Pause/stop/reload did not leave a clear stable recoverable state.

## Rejected approach

Do not treat source markers, syntax checks, schema presence, capability strings, or generated-code inspection as proof that concurrency, evidence atomicity, plan binding, refresh reconciliation, or recovery semantics work.

The 2026-09-03 qualification workflow checked that coordination code and schema structures existed and parsed. It did not execute the real backend lifecycle against two projects and did not drive the generated UI through state transitions. Those checks were incorrectly allowed to satisfy behavioral gates in the handoff decision.

## Required replacement

Before another owner handoff, qualification must execute the exact generated candidate and prove behavior with a stateful harness:

- create two isolated projects and run overlapping lifecycle work;
- prove Project B continues independently while Project A mutates;
- establish a committed evidence revision, start a replacement index, then cancel/fail it and prove the prior revision remains queryable and plan-eligible;
- create a plan and prove exact evidence revision binding before and after a newer successful evidence commit;
- exercise pause, stop, and process restart and prove durable terminal/interrupted states with no stale completion;
- drive the generated UI with a real DOM/browser harness or equivalent event/state test and prove polling does not reset selection, tab, picker/modal, search, focus, form edits, or scroll;
- require every behavioral assertion to pass before the installer can emit owner-test readiness.

## Lineage consequence

Build `2026.09.03.sot-turn01-coordination-1` is rejected evidence only and must not become the implementation ancestor for the next candidate. Rebuild from the governed accepted pre-base/Base integration lineage and reapply only behaviorally qualified coordination changes.
