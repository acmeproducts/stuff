# GY-031 — R9 Active-now qualifier inserted WIP before lazy schema initialization completed

Date: 2026-09-06
Status: QUALIFICATION FAILURE — PRE-CUTOVER

## Evidence

The R9 installer passed tool, database, live-backend, backend parse, UI contract, and database behavior gates. The Active-now fixture again became `Interrupted` before the assertion.

The exact cause is now identified in the qualified backend: `ensureSchema()` is lazy. Requiring the module does not initialize schema/recovery. The first call to `rows()`/`listProjects()` runs startup recovery and intentionally marks any existing `Queued`/`WIP` processing run and active project operation as interrupted. The fixture process wrote its `ready` file immediately after `require()`, so the installer inserted the synthetic active operation before startup recovery had actually run.

Observed result retained the expected progress counters (`40 / 100`) but state became `Interrupted`, lifecycle returned to `idle`, and `active_operation_id` was cleared.

No cutover occurred.

## Governing correction

Do not alter startup recovery and do not change the R9 product candidate. In the isolated qualifier process, force one harmless database read immediately after `require()` so `ensureSchema()` and startup recovery finish against the clean backup. Only then signal readiness, insert the governed synthetic active operation, and assert the same already-initialized process reports WIP 40/100.
