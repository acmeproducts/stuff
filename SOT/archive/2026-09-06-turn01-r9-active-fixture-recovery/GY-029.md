# GY-029 — R9 active-work qualifier invoked startup recovery on a synthetic orphan run

Date: 2026-09-06
Status: QUALIFICATION FAILURE — PRE-CUTOVER

## Evidence

The corrected R9 installer passed database behavior against a complete SQLite backup, then failed its Active-now fixture gate.

The fixture inserted only a `processing_runs` row with state `WIP`. Requiring the backend module invokes startup recovery. Because the fixture did not also create the durable `project_operations` ownership record and project active-operation pointer required by schema-5 coordination, startup recovery correctly classified that synthetic run as `Interrupted`.

Observed fixture result retained the expected progress counters (`40 / 100`) but state became `Interrupted`.

The owner repeated the same immutable installer and reproduced the same deterministic failure. No cutover occurred.

## Governing correction

Do not weaken startup recovery and do not change the R9 product candidate. Fix the qualifier fixture so it represents a legitimate active schema-5 operation: create the project with active operation/generation/lifecycle, create matching running `project_operations`, and bind the processing run to the same operation/generation. Then require the backend and assert WIP progress remains visible.
