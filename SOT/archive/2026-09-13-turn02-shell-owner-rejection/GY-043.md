# GY-043 — Turn 02 shell reset rejected

**Date:** 2026-09-13

## Rejected state

The first Turn 02 reset successfully cleared mutable SOT data and installed a fresh database, but the owner rejected the product direction because it reduced SOT to a thin browser shell rather than preserving the established volume-based, persistent, multi-threaded single-source-of-truth service architecture.

## Failure class

Architectural regression caused by simplifying the engine instead of simplifying only the control surface.

## Permanent negative rule

A reset may clear mutable data and replace the owner-facing UI, but it must not replace the persistent SOT engine with a browser-owned or script-like workflow.

Required foundation:

- persistent Node service;
- SQLite durable state;
- physical volumes as first-class storage truth;
- Source / Target / Backup roles assigned from discovered storage;
- background server-side indexing/fingerprinting;
- bounded worker pool and observable work state;
- browser as API client only;
- browser closure cannot stop work.

Python may be used to compose or qualify a release but is not the deployed application engine.

## Correction

Turn 02 resumes from the pinned qualified volume-aware Base-22 backend source lineage and adds a new standalone owner-facing Storage / SSOT / Work control surface. The rejected shell is evidence only and is not an implementation ancestor.
