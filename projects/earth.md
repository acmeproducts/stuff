## Decisions locked
- **Asset hosting:** Self-contained single HTML file; Babylon.js from CDN with dual-CDN loader (cdn.babylonjs.com → cdn.jsdelivr.net → unpkg). No build step, no local assets.
- **Start location:** San Francisco, CA, USA (37.7749°N, 122.4194°W).
- **Mobile controls (M3.4, owner-directed):** Twin virtual touch controls as DOM overlays, no assets — LEFT: floating stick (base ring appears where a left-half thumb lands, knob follows within a fixed radius, vector clamped to magnitude 1) drives camera-relative movement each frame (delta-time scaled; walk mode uses the camera heading projected to the ground plane, fly mode uses the full look direction; speed = stick magnitude × configured top speed); RIGHT: dragging on the right half of the screen rotates the camera (look-damping setting applies, invert-Y respected); JUMP button bottom-right in walk mode (vertical velocity + gravity, grounded via worldHeight). Babylon's built-in touch camera input is disabled so look/pinch never double-fire; pinch zoom continues to work (stick, look, and pinch tracked as separate pointer roles). Controls appear automatically on the first touch interaction (AUTO), with a persisted settings override AUTO/ON/OFF; desktop WASD/pointer-lock/wheel behavior unchanged; sticks hide while the settings modal is open.
- **Diagnostics:** On-screen HUD only, never console-only: FPS, lat/lon, altitude, mode (walk/fly), loaded tile count, per-service source status (CDN / elevation / land cover / OSM / imagery: OK or PROC-fallback).
- **Secrets hygiene:** No tokens or credentials in plan, code, or persisted thread state — ever. Reference repo is public; runtime data services need no keys.
- **Build verification:** Every code build stamps a BUILD tag (date + milestone id) onto the HUD so the owner can confirm which file version is actually loaded in the browser.
- **Governance minimization (owner directive 2026-09-29):** no redundant checkpoint turns; if a pre-code checkpoint for a milestone already exists in the ledger, the next turn writes that milestone's code directly.
- **Settings persistence (M3.2):** user settings (detail preset, walk/fly speed, time of day, look sensitivity, invert-Y, last position) persist to localStorage and restore on load; jump-to-location performs a FULL re-origin (recompute origin tile, clear tile cache, rebuild ring, respawn camera) so teleport works worldwide without floating-point drift. M3.3 adds the imagery toggle; M3.4 adds the touch-controls AUTO/ON/OFF override; M6 adds weather/season/cycle state.
- **Zoom model (M3.2):** mouse wheel and two-finger pinch adjust camera FOV as a 1–8× zoom factor (base FOV ÷ factor); pinch tracked via pointer events (two active pointers), independent of Babylon's built-in touch handling which is disabled for pinch to avoid conflicts. M3.4 reconciles pointer roles: a left-half first touch claims the move stick; remaining canvas touches drive look (one finger) or pinch zoom (two fingers).

Esri World Imagery (`https://server.arcgisonline.com/ArcGIS/rest/services/World_Imagery/MapServer/tile/{z}/{y}/{x}`) is the primary source: public, no API key, CORS-enabled, worldwide, and served on the same Web-Mercator z/x/y grid our terrain tiles already use (z15). Fetched per tile as blob → objectURL → Babylon texture, applied per-tile (each terrain mesh gets its own material instance so one slow image never blocks others); failure → per-tile fallback to the existing vertex-color appearance, counted on HUD as IMG PROC. Settings modal gains an imagery ON/OFF toggle. The earlier "optional OSM overlay, off by default" note is superseded: that referred to OSM standard map tiles; M3.3 adopts satellite imagery as the default base layer per explicit owner directive. Esri terms require attribution — an imagery credit line is shown on the HUD. **2026-09-30 addendum:** the M3.3 code path rendered the credit only in-plan; M4 adds the actual always-visible "Imagery © Esri & contributors" HUD credit while imagery is on. **Shipped visibly in M4 (confirmed in artifact).**

## Architecture (pinned)
- **Coordinates:** Web Mercator tile math; base terrain at zoom 15 (~1.2 km tiles at equator); lat/lon ↔ tile/pixel conversions in-app; horizontal meters locally scaled by cos(latitude) so horizontal and vertical units match.
- **Elevation:** Terrarium PNG tiles from the public elevation-tiles-prod S3 endpoint (`/terrarium/{z}/{x}/{y}.PNG`, CORS-enabled). Decode: `h = R*256 + G + B/256 − 32768` meters. Fallback: seeded fBm noise heightfield (globally continuous across tiles) so terrain always renders (HUD flags SRC: PROC); tiles built instantly from fallback upgrade in place when real elevation arrives; retry on tile re-entry after unload. Fetch hardening (M3.1): alternate-host fallback chain, 12 s timeout, 6-way concurrency cap, wrapped/clamped tile coordinates, failures reported as a quiet HUD NET-fail counter (no error-box spam).
- **Imagery (M3.3):** Esri World Imagery z15 tiles matched 1:1 to terrain tiles (`server.arcgisonline.com` primary; `services.arcgisonline.com` mirror as fallback host), fetched as blob with the same 12 s timeout / concurrency queue as elevation, decoded via Image → Babylon DynamicTexture (or direct objectURL texture), applied to the tile's own StandardMaterial clone with `diffuseTexture`; vertex colors kept as fallback when the image fails (HUD IMG: OK n / PROC n) and as the imagery-OFF mode. Texture sampling: bilinear, anisotropic filtering where available; material specular stays black, ambient lifted so shaded slopes stay readable. Attribution string "Imagery © Esri & contributors" on HUD (made visible in M4).
- **Sky & lighting (M3.3):** replace flat-emissive skybox with a vertical-gradient sky (procedural gradient texture on the sky sphere/box: zenith → horizon, day/night aware, still driven by the time-of-day slider); sun gets a warm tint near horizon, hemisphere ground color darkened for contrast; fog color matched to horizon color so terrain fades naturally instead of cutting to solid blue.
- **Mobile navigation (M3.4):** pointer-role state machine on canvas touch pointers — first left-half touch claims the floating move stick (base at touch point, knob follows, vector normalized to ≤1); any other touch is a look finger (one) or a pinch pair (two, existing FOV-zoom math reused); per frame the stick vector displaces the camera (engine delta time × mode top speed × magnitude; walk = heading projected to ground, fly = full forward vector); JUMP sets vertical velocity, gravity integrates each frame, landing clamps to worldHeight + eyeHeight and the walk-mode ground snap is skipped while airborne; UniversalCamera keyboard/mouse inputs untouched for desktop; Babylon's built-in touch camera input removed; JUMP + stick elements sit below the gear/modal z-index and hide while the modal is open.
- **Land cover / biomes (M4):** PRIMARY — Copernicus LCFM LCM-10 V1 classification windows via Terrascope public TiTiler (nearest-neighbour, class codes → ocean/beach/grass/forest/rock/snow/desert/cropland/urban), driving vegetation scatter and (imagery-off/failed) vertex colors. STAC collection: `https://stac.terrascope.be/collections/lcfm-lcm-10`; coverage 60 S–83 N (outside → fallback). TiTiler base pinned as `https://titiler.terrascope.be`; tile template (primary): `/cog/tiles/WebMercatorQuad/{z}/{x}/{y}@1x.png?url={assetCogHref}&resampling=nearest`; fallback pattern: `/stac/tiles/WebMercatorQuad/{z}/{x}/{y}@1x.png?collection=lcfm-lcm-10&item={itemId}&assets={assetId}&resampling=nearest`; asset/item href discovered at runtime via the STAC collection endpoint, then cached. Circuit breaker: after N consecutive failures the LC fetch chain disables itself (HUD shows LC: PROC) so a dead endpoint is never hammered; procedural biomes stay live. Any fetch/decode/coverage failure → FALLBACK — per-vertex procedural classification from latitude, elevation, moisture noise; bare-ground color when class unknown. Biome classification stored per tile (256×256 class grid) so vertex colors, scatter, and water placement all read the same source; procedural→TiTiler upgrade rebuilds the tile mesh and rescatter in place. **STATUS: landed, confirmed in artifact 2026-09-30.**
- **Water (M4):** sea-level (0 m) animated water plane per terrain tile (semi-transparent blue, specular highlight, gentle vertex/alpha wave animation via render loop); renders on every tile so coastlines, bays, and lakes read immediately; never blocks terrain. **STATUS: landed (single player-following plane covering the ring), confirmed 2026-09-30.**
- **Vegetation (M4):** thin-instance trees (trunk + canopy cones) and grass tufts scattered per tile from the biome grid — forest/grass/cropland get density-scaled scatter, ocean/beach/desert/snow/urban get none; instances seeded from tile coords so scatter is stable across LOD rebuilds; disposed with the tile; HUD VEG counter totals live instances. **STATUS: landed, confirmed 2026-09-30.**
- **Roads & buildings (M5, build written 2026-09-30):** Overpass API (`https://overpass-api.de/api/interpreter` primary, `https://overpass.kumi.systems/api/interpreter` mirror) — one debounced bbox query per area (~1.5 s after the player settles or after a teleport; bbox ≈ streamed ring extent, lat/lon derived from the inverse Mercator math already in-app), POST body `data=[out:json][timeout:25];(way["highway"](S,W,N,E);way["building"](S,W,N,E););out geom;`, 25 s AbortController timeout. Roads: each way's node lat/lons → world coords via the existing tile math, heights sampled with `worldHeight`, ribbon mesh draped on terrain (+0.15 m offset, no z-fighting), width by highway class (motorway 12 m, trunk/primary 10, secondary 8, tertiary/residential 6, service 4, footway/path/cycleway 2.5), dark asphalt color, merged per area chunk to bound draw calls. Buildings: closed-way footprints triangulated (fan for convex-ish, fallback bbox if degenerate) and extruded to flat-topped boxes; height from `height` tag, else `building:levels` × 3, else seeded 8–22 m; base sunk 1 m into terrain; per-building seeded pastel tint; merged per chunk. Robustness: exponential backoff on HTTP 429/5xx (start 5 s, ×2, cap 60 s), in-memory cache keyed by rounded tile area, circuit breaker after 3 consecutive failures (stop hammering, HUD OSM: PROC until next teleport/reset), all city meshes disposed + rebuilt on teleport/re-origin. Fallback + beyond coverage: deterministic procedural city per tile — seeded street grid (spacing ~120 m) drawn as ribbons along terrain + procedural buildings along street edges with door openings (visual enterability), so HUD always shows either OSM OK n features or PROC and buildings are present either way. Perf: merged meshes per chunk (roads one mesh, buildings one mesh per area), build cost amortized across frames if large (chunk way lists), city meshes excluded from fog wash (standard materials, fog applies naturally).
- **Streaming:** Ring of tiles centered on player (start 5×5, quality-scalable via M3.2 detail presets: LOW ring 1–2 / LOD 48/24/12, MED ring 2 / LOD 96/48/24, HIGH ring 3 / LOD 144/72/36), LOD by Chebyshev distance, skirt geometry (~14 m drop) on every tile edge to hide seams, tile cache + unload outside radius (evict beyond ring radius + 1); architecture expandable toward the reference 33×33 grid.
- **Settings UI (M3.2):** gear (⚙) button opens a modal panel (pointer-events enabled, canvas input suspended while open) containing: detail preset selector, walk/fly top-speed sliders, time-of-day slider (drives sun direction/intensity, hemisphere light, sky emissive, fog and clear color), jump-to-location (lat/lon number inputs + preset buttons: San Francisco, New York, London, Tokyo, Sydney, Mount Everest, Grand Canyon), look-sensitivity slider, invert-Y toggle. All changes apply live and persist to localStorage. **M3.3 adds:** satellite imagery ON/OFF toggle. **M3.4 adds:** touch-controls override (AUTO/ON/OFF). **M6 adds:** day/night cycle AUTO/MANUAL control, rain toggle, season selector (AUTO/spring/summer/autumn/winter), cloud cover indicator.
- **Weather/time (M6):** cloud billboards (procedural soft sprite, drifting, fog-exempt, wrapping around the player), rain particle system (camera-following emitter) with fog density boost while active, automatic time-of-day cycle advancing `settings.tod` per frame (manual slider drag pauses it; modal resume control), season system (AUTO from date, manual override) shifting vegetation + fallback terrain palette. All weather/season state persists with settings; diagnostics stay on the HUD (WX line).
- **Persistence:** localStorage save/load of position, time-of-day, season, quality settings (M3.2 ships settings + position persistence; M3.3 adds imagery toggle; M3.4 adds touch-controls override; M6 adds weather/season/cycle state; M7 completes full-state save/load).

## Risk register
- CDN blocked → try 3 CDNs in order; verify the BABYLON global after each script load; if all fail, show on-screen fatal error (never silent).
- Terrarium 404/429/CORS → per-tile fBm fallback; HUD flags PROC; retry on tile re-entry; failures counted quietly on HUD, not spammed.
- Esri imagery unavailable/slow/CORS-blocked → per-tile fallback to vertex-color appearance (terrain still renders), HUD IMG PROC count, mirror host retry, never blocks elevation or streaming; imagery OFF toggle always available.
- Imagery attribution requirement → HUD credit line "Imagery © Esri & contributors" always visible while imagery layer is on (ships visibly in M4).
- TiTiler unavailable/slow/out-of-coverage (60 S–83 N) → per-tile procedural biome classification; HUD flags PROC; land cover never blocks terrain render; circuit breaker stops repeated hammering of a dead endpoint.
- Overpass rate-limit → exponential backoff, in-memory cache, procedural grid fallback; HUD flags. M5 adds: 25 s query timeout, debounce so walking never fires a query storm, circuit breaker so a dead Overpass never blocks city fallback.
- Overpass bbox too large / dense city → cap bbox to ring extent (~2.5 km), `out geom` with way limit, chunk way processing across frames, merged meshes to bound draw calls; worst case falls back to procedural city for that area.
- Road ribbons on steep terrain → drape by sampling worldHeight per node with a small +0.15 m lift; segments subdivided when long so hills don't cut through ribbons.
- City meshes vs teleport → all city meshes are owned by an area container disposed in teleport() alongside tiles; rebuilds fire after the ring settles at the new origin.
- Phone perf → quality presets (LOW/MED/HIGH, shipped in M3.2) scale subdivisions, ring radius, vegetation density, particles; M3.3 adds ~25 texture decodes per ring rebuild — decoded through the existing 6-way queue so streaming never stalls; if decode cost hurts on LOW, drop imagery resolution via canvas downscale. M4 vegetation uses thin instances (one draw call per species per tile) so scatter stays cheap on phones. M5 keeps city geometry merged per area chunk (≤ a handful of extra draw calls) and skips building extrusion on LOW beyond the center area. M6 clouds are a handful of alpha billboards and rain one particle system; LOW preset reduces particle/cloud counts.
- Build-env fetch failures → irrelevant at runtime; app validates services live in the browser and reports on HUD.
- Owner cannot tell which build is loaded → BUILD tag stamped on HUD every build.
- Owner cannot tell whether console errors remain → on-screen error box traps every window.onerror and unhandledrejection; empty box = clean console.
- Process churn frustrates owner → reuse logged checkpoints; one file write per turn always lands as either the planned fix or the next milestone's code, never meta-only twice in a row.
- Jump-to-location far from origin → floating-point drift / stale tiles; mitigated by full re-origin teleport (recompute origin tile, dispose all tiles, rebuild ring, respawn) rather than raw camera move. M5 city meshes join the same dispose/rebuild path.
- Settings modal on touch → canvas must not rotate/zoom while interacting with modal: modal container has pointer-events:auto and input handlers check event target / modal-open flag.
- Pinch conflicts with Babylon touch camera input → pinch zoom implemented on raw pointer events; Babylon touch input for camera rotation limited to single-pointer drags. M3.4 goes further: Babylon's built-in touch camera input is removed entirely and all touch is routed through our pointer-role state machine (stick / look / pinch), eliminating double-rotation.
- Virtual sticks vs modal/gear overlap → sticks hide while the modal is open; buttons keep pointer-events:auto at a higher z-index; stick claims ignore touches that begin on UI elements.
- Jump vs walk-mode ground snap → the existing per-frame ground clamp applies only when grounded (no vertical velocity and at/below ground); airborne frames integrate gravity instead.
- Touch-laptop false positives → AUTO mode shows touch controls only after the first real touch-pointer interaction; ON/OFF override in settings covers edge cases.
- Stick + pinch cross-talk → pointer roles: left-half first touch = stick; subsequent touches = look (one) or pinch (two); roles release on pointerup/pointercancel.
- Per-tile material clones (M3.3) → more draw-call state changes; acceptable at 9–49 tiles, revisit at M8 if ring grows toward 33×33 (consider texture atlas or shared-material array then).
- M4 biome colors over satellite imagery → would regress the owner-mandated realistic look; locked decision: biomes affect scatter + fallback/off mode only.
- M4 water plane vs terrain below sea level → semi-transparent plane at 0 m with depth tested normally; terrain below 0 m remains visible through it; no z-fighting because plane sits at constant y=0 and terrain rarely equals exactly 0 over a large area (skirt edges excluded from water).
- M4 scatter on LOD rebuild → scatter seeded from tile coordinates (deterministic), so reseeding after an LOD or biome upgrade reproduces identical placement; instances disposed with tile extras on eviction/teleport.
- M5 buildings over vegetation scatter → buildings and trees may overlap visually in M5; acceptable at this fidelity (M8 polish can mask scatter under building footprints).
- M6 auto-cycle vs manual time slider → dragging the slider pauses the cycle (manual wins); a modal resume control restarts it; HUD WX line shows AUTO/MANUAL so state is never ambiguous.
- M6 rain fog boost vs distance visibility → fog density multiplies (not replaces) the base value while raining; toggling rain off restores the exact base density.
- M6 season recolor vs satellite imagery → season palette shifts apply to vegetation instance colors and the biome/fallback vertex-color look only, never over photo textures — same locked rule as M4.
