Milestones below are a build ORDER, not scope cuts: every feature ships.

## Decisions locked
- **Asset hosting:** Self-contained single HTML file; Babylon.js from CDN with dual-CDN loader (cdn.babylonjs.com → cdn.jsdelivr.net → unpkg). No build step, no local assets.
- **Start location:** San Francisco, CA, USA (37.7749°N, 122.4194°W).
- **Mobile controls:** Twin virtual sticks — left move/turn, right look — plus buttons for jump, fly toggle, settings. WASD + pointer-lock mouse on desktop.
- **Diagnostics:** On-screen HUD only, never console-only: FPS, lat/lon, altitude, mode (walk/fly), loaded tile count, per-service source status (CDN / elevation / land cover / OSM / imagery: OK or PROC-fallback).
- **Secrets hygiene:** No tokens or credentials in plan, code, or persisted thread state — ever. Reference repo is public; runtime data services need no keys.
- **Build verification:** Every code build stamps a BUILD tag (date + milestone id) onto the HUD so the owner can confirm which file version is actually loaded in the browser.
- **Governance minimization (owner directive 2026-09-29):** no redundant checkpoint turns; if a pre-code checkpoint for a milestone already exists in the ledger, the next turn writes that milestone's code directly.
- **Settings persistence (M3.2):** user settings (detail preset, walk/fly speed, time of day, look sensitivity, invert-Y, last position) persist to localStorage and restore on load; jump-to-location performs a FULL re-origin (recompute origin tile, clear tile cache, rebuild ring, respawn camera) so teleport works worldwide without floating-point drift.
- **Zoom model (M3.2):** mouse wheel and two-finger pinch adjust camera FOV as a 1–8× zoom factor (base FOV ÷ factor); pinch tracked via pointer events (two active pointers), independent of Babylon's built-in touch handling which is disabled for pinch to avoid conflicts.
- **Imagery as the base terrain texture (M3.3, owner-directed 2026-09-30):** satellite imagery is the DEFAULT-ON terrain appearance — plain height-band vertex colors alone were rejected by the owner as "not recognizable." Esri World Imagery (`https://server.arcgisonline.com/ArcGIS/rest/services/World_Imagery/MapServer/tile/{z}/{y}/{x}`) is the primary source: public, no API key, CORS-enabled, worldwide, and served on the same Web-Mercator z/x/y grid our terrain tiles already use (z15). Fetched per tile as blob → objectURL → Babylon texture, applied per-tile (each terrain mesh gets its own material instance so one slow image never blocks others); failure → per-tile fallback to the existing vertex-color appearance, counted on HUD as IMG PROC. Settings modal gains an imagery ON/OFF toggle. The earlier "optional OSM overlay, off by default" note is superseded: that referred to OSM standard map tiles; M3.3 adopts satellite imagery as the default base layer per explicit owner directive. Esri terms require attribution — an imagery credit line is shown on the HUD.
- **M4 interplay (locked 2026-09-30):** when M4 land cover lands, biome classification drives vegetation scatter and the vertex-color fallback look; with imagery ON, biome colors must not replace photo textures (blend subtly or apply only when imagery is off/failed), so the owner-visible "real world" look is never regressed.

## Architecture (pinned)
- **Coordinates:** Web Mercator tile math; base terrain at zoom 15 (~1.2 km tiles at equator); lat/lon ↔ tile/pixel conversions in-app; horizontal meters locally scaled by cos(latitude) so horizontal and vertical units match.
- **Elevation:** Terrarium PNG tiles from the public elevation-tiles-prod S3 endpoint (`/terrarium/{z}/{x}/{y}.PNG`, CORS-enabled). Decode: `h = R*256 + G + B/256 − 32768` meters. Fallback: seeded fBm noise heightfield (globally continuous across tiles) so terrain always renders (HUD flags SRC: PROC); tiles built instantly from fallback upgrade in place when real elevation arrives; retry on tile re-entry after unload. Fetch hardening (M3.1): alternate-host fallback chain, 12 s timeout, 6-way concurrency cap, wrapped/clamped tile coordinates, failures reported as a quiet HUD NET-fail counter (no error-box spam).
- **Imagery (M3.3):** Esri World Imagery z15 tiles matched 1:1 to terrain tiles (`server.arcgisonline.com` primary; `services.arcgisonline.com` mirror as fallback host), fetched as blob with the same 12 s timeout / concurrency queue as elevation, decoded via Image → Babylon DynamicTexture (or direct objectURL texture), applied to the tile's own StandardMaterial clone with `diffuseTexture`; vertex colors kept as fallback when the image fails (HUD IMG: OK n / PROC n) and as the imagery-OFF mode. Texture sampling: bilinear, anisotropic filtering where available; material specular stays black, ambient lifted so shaded slopes stay readable. Attribution string "Imagery © Esri & contributors" on HUD.
- **Sky & lighting (M3.3):** replace flat-emissive skybox with a vertical-gradient sky (procedural gradient texture on the sky sphere/box: zenith → horizon, day/night aware, still driven by the time-of-day slider); sun gets a warm tint near horizon, hemisphere ground color darkened for contrast; fog color matched to horizon color so terrain fades naturally instead of cutting to solid blue.
- **Land cover / biomes:** PRIMARY — Copernicus LCFM LCM-10 V1 classification windows via Terrascope public TiTiler (nearest-neighbour, class codes → ocean/beach/grass/forest/rock/snow/desert/cropland/urban), driving vegetation scatter and (imagery-off/failed) vertex colors. STAC collection: `https://stac.terrascope.be/collections/lcfm-lcm-10`; coverage 60 S–83 N (outside → fallback). TiTiler base pinned as `https://titiler.terrascope.be`; tile template (primary): `/cog/tiles/WebMercatorQuad/{z}/{x}/{y}@1x.png?url={assetCogHref}&resampling=nearest`; fallback pattern: `/stac/tiles/WebMercatorQuad/{z}/{x}/{y}@1x.png?collection=lcfm-lcm-10&item={itemId}&assets={assetId}&resampling=nearest`; asset/item href discovered at runtime via the STAC collection endpoint, then cached. Any fetch/decode/coverage failure → FALLBACK — per-vertex procedural classification from latitude, elevation, moisture noise; bare-ground color when class unknown. HUD flags which source is live.
- **Water:** Sea-level (0 m) animated water plane per tile; lakes where elevation ≈ flat below threshold.
- **Roads & buildings:** Overpass API (overpass-api.de primary, kumi.systems mirror) bbox queries around player, debounced, cached; roads as terrain-conforming ribbons, building footprints extruded to boxes. Fallback + beyond range: procedural street grid and procedural enterable buildings along roads.
- **Streaming:** Ring of tiles centered on player (start 5×5, quality-scalable via M3.2 detail presets: LOW ring 1 / LOD 48/24/12, MED ring 2 / LOD 96/48/24, HIGH ring 3 / LOD 128/64/32), LOD by Chebyshev distance, skirt geometry (~14 m drop) on every tile edge to hide seams, tile cache + unload outside radius (evict beyond ring radius + 1); architecture expandable toward the reference 33×33 grid.
- **Settings UI (M3.2):** gear (⚙) button opens a modal panel (pointer-events enabled, canvas input suspended while open) containing: detail preset selector, walk/fly top-speed sliders, time-of-day slider (drives sun direction/intensity, hemisphere light, sky emissive, fog and clear color), jump-to-location (lat/lon number inputs + preset buttons: San Francisco, New York, London, Tokyo, Sydney, Mount Everest, Grand Canyon), look-sensitivity slider, invert-Y toggle. All changes apply live and persist to localStorage. **M3.3 adds:** satellite imagery ON/OFF toggle.
- **Vegetation:** Instanced meshes (thin instances) for trees/grass scattered per biome, density scaled by quality preset.
- **Weather/time:** Cloud billboards, rain particle system, fog density control; time-of-day cycle drives sun/fog/light (M3.2 ships a manual time-of-day slider; M6 adds the automatic cycle); season system shifts palette and vegetation colors.
- **Persistence:** localStorage save/load of position, time-of-day, season, quality settings (M3.2 ships settings + position persistence; M3.3 adds imagery toggle; M7/M6 extend).

## Risk register
- CDN blocked → try 3 CDNs in order; verify the BABYLON global after each script load; if all fail, show on-screen fatal error (never silent).
- Terrarium 404/429/CORS → per-tile fBm fallback; HUD flags PROC; retry on tile re-entry; failures counted quietly on HUD, not spammed.
- Esri imagery unavailable/slow/CORS-blocked → per-tile fallback to vertex-color appearance (terrain still renders), HUD IMG PROC count, mirror host retry, never blocks elevation or streaming; imagery OFF toggle always available.
- Imagery attribution requirement → HUD credit line "Imagery © Esri & contributors" always visible while imagery layer is on.
- TiTiler unavailable/slow/out-of-coverage (60 S–83 N) → per-tile procedural biome classification; HUD flags PROC; land cover never blocks terrain render.
- Overpass rate-limit → exponential backoff, in-memory cache, procedural grid fallback; HUD flags.
- Phone perf → quality presets (LOW/MED/HIGH, shipped in M3.2) scale subdivisions, ring radius, vegetation density, particles; M3.3 adds ~25 texture decodes per ring rebuild — decoded through the existing 6-way queue so streaming never stalls; if decode cost hurts on LOW, drop imagery resolution via canvas downscale.
- Build-env fetch failures → irrelevant at runtime; app validates services live in the browser and reports on HUD.
- Owner cannot tell which build is loaded → BUILD tag stamped on HUD every build.
- Owner cannot tell whether console errors remain → on-screen error box traps every window.onerror and unhandledrejection; empty box = clean console.
- Process churn frustrates owner → reuse logged checkpoints; one file write per turn always lands as either the planned fix or the next milestone's code, never meta-only twice in a row.
- Jump-to-location far from origin → floating-point drift / stale tiles; mitigated by full re-origin teleport (recompute origin tile, dispose all tiles, rebuild ring, respawn) rather than raw camera move.
- Settings modal on touch → canvas must not rotate/zoom while interacting with modal: modal container has pointer-events:auto and input handlers check event target / modal-open flag.
- Pinch conflicts with Babylon touch camera input → pinch zoom implemented on raw pointer events; Babylon touch input for camera rotation limited to single-pointer drags.
- Per-tile material clones (M3.3) → more draw-call state changes; acceptable at 9–49 tiles, revisit at M8 if ring grows toward 33×33 (consider texture atlas or shared-material array then).
- M4 biome colors over satellite imagery → would regress the owner-mandated realistic look; locked decision: biomes affect scatter + fallback/off mode only.
- Credentials in chat → never persist tokens in plan, code, or thread state; scrub/reset any that leak into persisted history before pushing (see SECURITY INCIDENT); treat exposed tokens as compromised.
- Thread-write conflicts (409) → refresh thread state, re-apply, retry once; never force-push over another writer blindly.
